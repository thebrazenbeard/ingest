# Ingest V1 Security Model

## Trust boundary

Every acquired payload is untrusted data. V1 never executes, imports, evaluates, shells, deserializes with unsafe object loaders, or otherwise grants code authority to acquired bytes.

## Local files

Configured `allowed_roots` must be absolute paths and are resolved before use. The CLI converts operator-supplied `--root` values such as `.` to absolute paths before policy construction; the Python policy API rejects relative roots because the same policy digest could otherwise mean different filesystem authority under different working directories. Inputs resolving outside those roots are rejected. When link following is disabled, symlink/junction traversal is rejected across the full input path, not only at the final filename. After path validation, V1 records a pre-open stat signature, opens the resolved path as a file descriptor (`O_NOFOLLOW` when the platform exposes it), compares stable cross-handle identity fields (device, inode/file identity, size, and modification time), reads at most `max_bytes + 1` through that descriptor, and performs a stronger same-descriptor post-read stability comparison that also includes change/creation time. Cross-handle `ctime` is deliberately excluded from the first comparison because Windows can report slightly different creation-time values through `stat()` and `fstat()` for an untouched file. Identity, size, or stable timestamp changes still fail acquisition. This materially narrows validation/open/read races, but it is not a formal cross-filesystem snapshot guarantee: platforms without stable inode semantics or `O_NOFOLLOW`, and hostile same-inode modifications that evade the compared metadata, remain outside the V1 guarantee.

## HTTP(S)

HTTPS is the default. Plain HTTP requires `allow_http=True`. Each requested/redirect URL is policy-checked, redirect count is bounded, reads are capped at `max_bytes + 1`, and a timeout is mandatory. A returned final URL is checked before its response body is consumed. Private, loopback, link-local, multicast, reserved, and unspecified destinations are denied by default.

The default stdlib V1 transport resolves each destination, rejects forbidden answers under policy, and connects directly to a validated IP instead of handing the hostname back to the socket layer for a second resolution. HTTPS still uses the original hostname for TLS certificate verification. This binds the default connection to the address set that actually passed policy validation. If a caller injects a custom opener, requested/final URLs are still policy-checked, but connection binding becomes that opener's responsibility.

Persisted HTTP provenance strips URL userinfo, query, and fragment from the human-readable locator. Exact requested/final URL distinctions remain bound by SHA-256 digests so credentials and secret query values are not written in plaintext.

## GitHub

Mutable refs are resolved to exact commits before content acquisition. The default GitHub API transport converts network, HTTP, and invalid-JSON failures to bounded acquisition failures; it also recomputes the returned file's Git object digest and rejects a blob identity that does not match the acquired bytes. `.json`, `.jsonl`, and `.ndjson` are parser-driving from their path extensions even if the host MIME database disagrees. Credentials are constructor/transport state and are never persisted in provenance objects or receipts. Exact commit/blob identity is evidence of source selection, not proof that repository content is safe or true.

## Structured parsing

JSON and JSONL use Python's data-only JSON parser and strict canonical serialization. Unsupported objects and non-finite numbers (`NaN`, `Infinity`, overflow to infinity) are not silently stringified or emitted as non-standard JSON. Claimed structured data that cannot be represented as strict JSON is quarantined after raw preservation; invalid structured message payloads are rejected before admission. No archive extraction is performed in V1, preventing archive-bomb/path-traversal classes from entering the core pipeline.

## Storage

Content blobs, records, receipts, and derivations are immutable create-only paths. A collision with different bytes/content raises a store conflict. Read paths are also integrity-checked: managed reads reject link redirection and mid-read mutation; JSON objects must match the store's canonical byte encoding; receipt bodies must match their persisted digest; derivation IDs are recomputed from a verified `normalize/PASS` receipt whose input/output artifact IDs match the derivation parent/child, and record verification requires that derivation receipt to carry the same deterministic ingest identity as the record. The receipt need not be the winning record observation's literal receipt ID because concurrent equivalent observations can race independently while sharing one stable derivation edge. Artifact verification compares declared size with the opened descriptor before reading bytes, then verifies exact size and SHA-256. Record reads verify referenced blob hashes/sizes/locators plus acquisition, persistence, normalization, status/error, warning, and commit-receipt consistency before returning. Managed components below the configured store root are checked for symlink/junction redirection before directory admission, existing-content comparison, temp-file publication, and create-only linking; link-like managed components fail with `StoreConflict`. The configured root itself remains caller-selected and is not reinterpreted as a managed child component. Missing storage directories are created one level at a time; after each new directory entry, the store attempts to `fsync` that directory's parent so the root and intermediate hierarchy participate in the durability boundary. First file publication writes and fsyncs a temporary file, then uses a create-only hard link so an existing immutable path is never overwritten; the temporary path is removed afterward. After a successful new hard-link publication, POSIX hosts attempt to open and `fsync` the containing directory so the final file entry participates in the same boundary. Python does not expose a portable Windows directory-`fsync` equivalent, and POSIX directory-sync failure is currently best-effort rather than surfaced as an ambiguous write failure, so V1 does not claim universal power-loss durability of directory metadata. Interrupted processes may leave store-owned `.tmp-*` files behind. V1 does not sweep them automatically: `cleanup_stale_temp_files()` is an explicit operator action with a 24-hour default finite/non-negative age guard, does not recurse through link-like managed directories, leaves unrelated names untouched, reports reclaimed bytes, and sync-attempts the containing directory after each deletion. Concurrent attempts for the same deterministic ingest identity may accept an already-created record only after comparing deterministic record semantics. The comparison uses source identity material and excludes non-identity source metadata, observation timestamps, and receipt IDs, which may legitimately differ between observations; semantic conflicts still fail. Accepted records bind a `record/READY` receipt before publication, and the immutable record's presence—not a later receipt—is the acceptance commit point.

## Logging and secrets

V1 stores bounded structured errors, not tracebacks. Adapters must not place authorization headers, tokens, cookies, credentials, or secret query parameters into `SourceRef` or receipt details. Future redaction policy belongs before persistence, never as a promise that a stored secret can later be made un-stored. These read-time checks detect corruption and internally inconsistent external modification; they are not an authenticity signature. An actor with full write access to the store can potentially rewrite content and recompute unkeyed hashes consistently. Strong authenticity requires a keyed signature or external trust anchor that V1 does not claim.
